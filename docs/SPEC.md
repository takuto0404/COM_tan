# COM単 学習Webアプリ 仕様書

- 版: v1.1(イメージ画像・端末時刻基準・連続進行・answer_labelを反映)
- 作成日: 2026-08-27
- 状態: 壁打ち完了・実装着手可

---

## 1. 概要

市販単語帳「COM単」の学習効果を高めるWebアプリ。例文穴埋め×音声4択のクイズを1日単位で繰り返し、5日で1セットを「完全記憶」に導く。ポイント・カレンダー・月間ランキングで継続を促す。

- 対象デバイス: **スマホ優先(モバイルファースト)**。PCでも崩れないレスポンシブ対応。
- 実データ規模: **約500セット(=約5,000語)**。開発時は仮データ**10セット(100語)**で作成し、スキーマ・UIは500セット規模を前提に設計する(一覧の仮想スクロール、集計のインデックス等)。

## 2. 用語定義


| 用語   | 定義                                     |
| ---- | -------------------------------------- |
| 単語   | COM単収載の1語。例文・音声・カテゴリ・(任意で)チップスを持つ      |
| セット  | 単語10問のまとまり。学習の最小実施単位                   |
| 問題   | 例文中の対象単語が穴埋めになったもの。選択肢は音声4択(No.1〜No.4) |
| チップス | 一部の単語に付く補足情報。正解後に表示され、既読チェックが必須        |
| イメージ画像 | 各単語に付く、単語と記憶を結びつけるための画像。**解答後に正誤を問わず表示する** |
| クリア  | 1セット10問を最後まで完走すること(誤答してもやり直して完走すればクリア) |
| 完全記憶 | **同一セットを異なる日に計5回クリア**した状態              |
| 1日   | **ユーザー端末のローカル日付**(端末タイムゾーンの0:00〜23:59)を1日とする |

### 3.1 メディアデータ(音声・画像)の前提

- 音声形式: MP3(1ファイル数十KB〜想定)。種類は「例文読み上げ」「選択肢単語読み上げ」の2系統。
- 画像形式: WebP または JPEG/PNG(単語1語につき1枚のイメージ画像。長辺1000px程度・100KB前後を推奨)。
- 保管: Supabase Storage の非公開バケット。配信は署名付きURL(有効期限つき)をサーバー側で発行。教材データは商材のため直リンク公開しない。
- 容量見積: 実データ5,000語で音声約1万ファイル+画像5,000枚。画像100KB/音声30KB前後なら合計約800MBで、Supabase無料枠(Storage 1GB)に収まるがやや逼迫する。**画像はWebP圧縮を必須**とし、超過が見えたら有料化($25/月、100GB)で解消する。
- **モバイルの自動再生制限対応**: iOS Safari等はユーザー操作なしの音声再生を禁止するため、セット開始は必ず「スタート」ボタンのタップから始め、そのジェスチャーでAudioContextをアンロックする。以降の自動再生はこれで可能になる。
- 体感速度: 問題nを解いている間に問題n+1のメディア(例文音声+選択肢音声4つ+イメージ画像)をプリフェッチする。

## 4. 機能要件

### 4.1 認証・アカウント

- 会員登録/ログイン: **メールアドレス+パスワード** または **Googleアカウント**(Supabase Auth)。
- メール登録時は確認メールによるアドレス検証を行う。パスワードリセットあり。
- 初回ログイン時に**ニックネーム**(ランキング表示名)を必須設定。全ユーザー間で一意。1〜12文字。後から変更可。
- ログアウト、退会(アカウント削除)を提供。退会時は学習記録も削除(ランキング集計から除外)。

### 4.2 ホーム画面

- **今日のセット**を1件自動提示する。優先順位:
  1. クリア回数1〜4回(完全記憶前)のセットのうち、**今日未実施**のものを「最終クリア日が古い順」に提示
  2. 該当がなければ**未着手のセット**をセット番号順に提示
  3. 全セットが完全記憶済み、または今日実施可能なセットがない場合はその旨を表示
- 「今日のセット」をクリアすると、続けて次の候補が同ロジックで提示される。**異なるセットであれば1日に何セットでも実施可**(同一セットは1日1回まで)。
- **連続進行がこのアプリの基本動線**: ユーザーは推奨セットをひたすら進めていく。結果画面の「次に進む」ボタンで、ホームに戻ることなく次の推奨セットへ直接続行できる。セット実施中〜結果画面の間に次の推奨セットのデータとメディアを先読みし、「次に進む」タップから次セット開始までを待ち時間なく滑らかにつなぐ。
- **単語帳コンプリート進捗**を表示:
`進捗率 = 全セットのクリア回数合計(各セット上限5) ÷ (セット数 × 5) × 100`(小数第1位まで)
- その他ホームに置く要素: 今日の獲得ポイント、連続学習日数(ストリーク)、カレンダー/ランキングへの導線。
- セット一覧画面も用意し、任意のセットを選んで実施できる(自動提示は推奨動線であって強制ではない)。各セットにクリア回数(0〜5)と完全記憶バッジを表示。500件想定のため仮想スクロール+カテゴリ絞り込みを付ける。

### 4.3 学習フロー(1セット=10問)

```
スタート(タップ=音声アンロック)
 └→ 問題表示
      ├ 例文(対象単語が空欄「____」)をテキスト表示
      ├ No.1→No.2→No.3→No.4 の選択肢音声を自動で順次再生
      ├ 各選択肢ボタンはタップでいつでも個別に再生し直せる
      ├ 回答は「選択肢を選ぶ → 決定ボタン」の2段階で確定
      │
      ├─ 正解 ──→ 正解表示+**イメージ画像**+例文音声(穴埋めが埋まった全文)を1回再生
      │            ├ チップスあり: チップス表示。「読んだ」チェックを付けないと次へ進めない
      │            └ 次の問題へ(10問目なら結果画面へ)
      │
      └─ 誤答 ──→ 答え(正解の単語)+**イメージ画像**を表示+例文音声を1周再生
                   └→ **同じ問題をその場で即やり直し**(正解するまで次へ進めない)
```

- **イメージ画像は解答が確定したタイミングで正誤を問わず必ず表示する**。単語と画像を結びつけて記憶させることが目的のため、答え・例文とともに1画面に収める(スクロールなしで見える配置)。
- 解答表示では例文の穴を実際の表記(活用形、`questions.answer_label`)で埋めた全文を表示する(見出し語をそのまま埋めると文法が壊れるため)。
- 選択肢の並び順(どの音声がNo.いくつか)はセット実施ごとにシャッフルする。やり直し時も再シャッフルする。
- 結果画面: 10問の一覧(初回正解/誤答あり)、獲得ポイント、当該セットのクリア回数(n/5)、完全記憶到達時は祝福演出。**「次に進む」ボタン**で次の推奨セットへ直接続行(4.2の連続進行)。次の推奨がない場合はホームへ誘導。
- **中断の扱い**: セット実施中に離脱した場合、そのセッションは破棄する。記録(クリア・ポイント)は10問完走時のみサーバーに保存される。同日中なら同セットを最初からやり直せる(未クリアのため1日1回制限に抵触しない)。

### 4.4 ポイント

- **セット完走で一律10pt**。誤答の有無は問わない(やり直して完走すれば10pt)。
- ただし**完全記憶(5回クリア)後の再挑戦は0pt**。再挑戦自体は1日1回制限のもとで無制限に可能で、進捗率にも影響しない(5/5のまま)。
- 付与判定はサーバー側で行う(後述 6.3)。クライアントの申告値は信用しない。

### 4.5 カレンダー

- 月表示のカレンダーに**日毎の獲得ポイント数**を表示(例: 日付セルに「30pt」)。
- 月の切り替え(前月/翌月)可。当月合計ポイントも表示。
- 0ptの日は空欄。データは自分のもののみ。

### 4.6 月間ランキング

- **当月(JST)の獲得ポイント合計**による全ユーザーランキング。
- 表示: **上位100人**(ニックネーム+ポイント+順位)と、**自分の順位・ポイントを別枠で常時表示**。
- 同点は同順位(競技順位方式: 1,2,2,4…)。
- 月初にリセット(=集計期間が変わるだけで、過去月の記録は保持)。前月ランキングの閲覧も可能。
- 更新頻度: リアルタイム集計が重い場合は5分程度のキャッシュを許容する。

### 4.7 管理画面(/admin)

管理者ロールを持つユーザーのみアクセス可(一般UIとは分離)。

1. **コンテンツ管理(CRUD)**
  - カテゴリ、セット、単語、問題(例文・穴埋め位置)、選択肢、チップスの登録・編集・削除
  - 音声ファイル(例文/単語)のアップロードと差し替え、ブラウザ上での試聴
  - イメージ画像のアップロードと差し替え、プレビュー表示
  - セットの公開/非公開フラグ(作成途中のセットを学習者に見せない)
2. **CSV/一括インポート**
  - 問題・選択肢・チップス・カテゴリをCSV(またはJSON)で一括投入。音声・画像はファイル名規約(例: `{word_id}_word.mp3` / `{question_id}_sentence.mp3` / `{word_id}_image.webp`)でZIP一括アップロードし、自動で紐付け
  - インポート時バリデーション(選択肢数=4、正解が1つ、音声・画像欠落の検出、例文に見出し語〈活用形含む〉が含まれるか)とエラーレポート表示
  - 500セット規模の投入を想定し、バックグラウンド処理+進捗表示
3. **ユーザー管理**
  - 一覧・検索(ニックネーム/メール)、利用停止(BAN)、ニックネーム強制変更(不適切名対応)、管理者権限の付与
4. **利用統計ダッシュボード**(優先度低)
  - DAU、日別セット実施数、登録者数推移、継続率、問題別の初回正答率(難易度分析用)

## 6. データモデル(PostgreSQL / Supabase)

### 6.1 テーブル定義(主要カラムのみ)

```
profiles            -- auth.usersと1:1
  id uuid PK (= auth.users.id)
  nickname text UNIQUE NOT NULL
  role text NOT NULL DEFAULT 'user'   -- 'user' | 'admin'
  is_banned boolean DEFAULT false
  created_at timestamptz

categories
  id uuid PK
  name text NOT NULL
  sort_order int NOT NULL

word_sets
  id uuid PK
  category_id uuid FK -> categories
  set_number int UNIQUE NOT NULL      -- 単語帳上の通し番号(1〜500)
  title text
  is_published boolean DEFAULT false

words
  id uuid PK
  set_id uuid FK -> word_sets
  position int NOT NULL               -- セット内の順序(1〜10)
  headword text NOT NULL              -- 単語
  meaning text                        -- 意味
  tip text                            -- チップス(NULL可)
  word_audio_path text NOT NULL       -- 単語読み上げ音声
  image_path text NOT NULL            -- イメージ画像(全単語必須)
  UNIQUE(set_id, position)

questions                             -- wordと1:1
  id uuid PK
  word_id uuid UNIQUE FK -> words
  sentence_text text NOT NULL         -- 例文。穴埋め位置は "{{blank}}" プレースホルダで表現
  answer_label text NOT NULL          -- 穴に入る語の例文中での表記(活用形。解答表示で全文を復元する)
  sentence_audio_path text NOT NULL   -- 穴埋めが埋まった全文の読み上げ音声

choices                               -- 1問につき4行
  id uuid PK
  question_id uuid FK -> questions
  audio_path text NOT NULL            -- 選択肢の単語読み上げ音声
  label text NOT NULL                 -- 答え表示用の単語テキスト
  is_correct boolean NOT NULL
  -- 制約: question_idごとに4行・is_correct=trueは1行(インポート時+DB制約で担保)

set_completions                       -- クリア記録(完走時のみINSERT)
  id uuid PK
  user_id uuid FK -> profiles
  set_id uuid FK -> word_sets
  completed_on date NOT NULL          -- JSTの日付
  points int NOT NULL                 -- 10 or 0(完全記憶後)
  first_try_correct_count int         -- 初回正解数(0〜10、統計用)
  created_at timestamptz
  UNIQUE(user_id, set_id, completed_on)   -- ★1日1回制限の物理担保

answer_logs                           -- 統計用(任意・非同期書き込みで可)
  user_id, question_id, was_first_try_correct boolean, attempt_count int, answered_at
```

### 6.2 導出値(テーブルを持たない)

- セットのクリア回数 = `count(set_completions where user_id, set_id)`(上限5にクランプして表示)
- 完全記憶 = クリア回数 ≥ 5
- 進捗率 = `sum(least(クリア回数,5)) / (公開セット数 × 5)`
- 日別ポイント = `sum(points) group by completed_on`
- 月間ランキング = `sum(points) where completed_on between 月初..月末 group by user_id order by desc`
  - `(user_id, completed_on)` にインデックス。負荷が出たらマテリアライズドビュー+5分リフレッシュに切替。

### 6.3 整合性・不正対策

- Supabase **RLS** を全テーブルに適用。学習記録は本人のみ読み書き、コンテンツは公開セットのみ一般ユーザーに読み取り許可、管理系はadminロールのみ。
- **クリア記録の書き込みはServer Action経由のみ**。サーバー側で以下を検証してからINSERTする:
  1. 対象セットが公開中である
  2. `completed_on` は**クライアントが端末のローカル日付(YYYY-MM-DD)として送信**する。サーバーはその日付が「サーバー現在時刻(UTC)から見て実在しうるローカル日付の範囲(UTC±26h相当)」に収まることを検証し、範囲外は拒否する(過去日・未来日の捏造防止。タイムゾーンの自由は保ちつつ大きな改ざんだけ弾く)
  3. `UNIQUE(user_id, set_id, completed_on)` に抵触しない(=その端末日付で未実施)
  4. ポイントは既存クリア回数から算出(5回以上済みなら0、それ以外は10)— クライアントからpointsは受け取らない
- 完走の正当性(本当に10問解いたか)はMVPでは厳密検証しない。将来必要ならセット開始時にサーバーでセッショントークンを発行し、開始〜完了の最短所要時間チェック等を追加する(拡張余地として記載)。

## 7. 非機能要件

- **性能**: 画面遷移はクライアントサイドルーティングで即時。クイズ中は次問題の音声をプリフェッチし、回答→次問題の待ち時間を体感ゼロに近づける。
- **対応環境**: iOS Safari / Android Chrome の最新2メジャーバージョン、PCはChrome/Edge/Safari。画面幅360px〜。
- **アクセシビリティ**: 選択肢ボタンは44px以上のタップ領域。再生中の選択肢を視覚的に明示(音が聞こえない環境でも状態が分かるように)。
- **セキュリティ**: RLS徹底、署名付きURLでの音声配信、管理画面はロールチェック+ミドルウェアでガード。
- **タイムゾーン**: 「1日」の判定・カレンダー表示・月間ランキングの集計期間は**ユーザーの端末ローカル日付**に従う。`completed_on` にはローカル日付を記録し、集計はその日付文字列ベースで行う(端末タイムゾーンの差により月間集計の締めがユーザーごとに数時間ずれることは許容する)。端末時刻の大幅な改ざんは 6.3 のサーバー検証窓で防ぐ。

## 8. テスト方針(Playwright)

- シード済みテストデータ(仮データ10セット)+テスト専用ユーザーでE2Eを実施。CI(GitHub Actions)で全実行。
- 音声はテスト時に実再生の完了を待たずに進められるよう、`data-testid` と再生状態のフックを用意する(無音の短尺ダミーMP3を使用)。
- 日付境界のテスト: 「1日」は端末時刻基準のため、Playwrightの `clock` APIでクライアント時刻を固定・進行させて「翌日になった」「月が替わった」を再現する。サーバーの受理窓検証(6.3)用に、テスト環境でのみサーバー現在時刻を注入できる環境変数も用意する。

主要シナリオ:

1. 会員登録(メール)→ニックネーム設定→ホーム表示
2. Googleログイン(モック or テストプロバイダ)
3. セット実施: 全問正解での完走、10pt付与、クリア回数の増加
4. 誤答フロー: 誤答→答え表示→同一問題のやり直し→正解で次へ
5. チップス: チェックを付けるまで「次へ」が押せない
6. 1日1回制限: 同日同セット再実施のブロック、別セットは実施可
7. 完全記憶: 5回目クリアでバッジ、6回目は0pt
8. カレンダーの日別ポイント表示、月送り
9. ランキング: 上位表示・自分の順位枠・月替わりでのリセット
10. 進捗率の計算表示
11. 管理画面: 問題CRUD、音声アップロード、CSVインポート(正常系+バリデーションエラー)、非公開セットが学習者に見えないこと
12. 権限: 一般ユーザーの `/admin` アクセス拒否、BANユーザーのログインブロック

## 10. 決定事項サマリ(壁打ち結果)

- 技術: Next.js + Supabase + Vercel、Playwright
- 完全記憶: 同一セットを異なる日に5回クリア
- ポイント: 完走で一律10pt、完全記憶後の再挑戦は0pt(再挑戦自体は可)
- 選択肢UX: 表示時にNo.1→4自動順次再生+個別再生可、選択→決定で回答確定
- 誤答: 答えと例文音声1周→その場で同一問題を即やり直し
- イメージ画像: 解答確定時に正誤を問わず必ず表示(単語と画像の結びつけが目的)
- チップス: 正解後に表示、既読チェック必須
- 提示ロジック: 進行中(1〜4回)の復習を古い順に優先、なければ新規。異なるセットなら1日何セットでも可
- 基本動線: 推奨セットの連続進行。結果画面「次に進む」で次セットへシームレスに続行(次セットは先読み)
- 日付判定: ユーザー端末のローカル日付基準(サーバーは受理窓で大幅な改ざんのみ防止)
- 例文中の単語は活用形でもよい(語形マッチングで穴埋め生成、`answer_label` に表記を保存)
- ランキング: 月間、上位100+自分の順位、ニックネーム制
- デバイス: スマホ優先
- データ: 仮10セット/実500セット、管理画面(CRUD・CSVインポート・ユーザー管理・統計)を仕様に含む
